# 连板股票池：数量与成交额趋势

2026-11-10 用户要求按交易日盘后记录连板股数量、合计成交额，并纳入复盘趋势。

## 统计口径

- 当日收盘涨停、连续涨停至少2天；排除ST、退市及沪深B股。以当日涨停来源覆盖范围为准，不宣称补齐该来源不覆盖的市场。
- 每天重新确定成员；不是固定组合，也不包含断板股或仅盘中触板股。N天M板不能代替连续涨停天数。
- 名单使用 `get_limit_up_list` 同批结果，连板天数复用 `utils.limit_identity.verified_streak`。缺字段和默认首板无法交叉核验时，总数量与总成交额均保留未知。
- 金额仅用同批 `tushare:daily.amount`：千元除以100000换算亿元，逐股加总后显示两位小数。日线接口不含盘后固定价格交易额，不是成交股数、封单额或净流入。
- 不使用旧涨停记录的 `amount_billion`，该字段在历史Tushare适配中存在单位错误，不能直接相加。
- 来源文档：[日线](https://tushare.pro/document/2?doc_id=27)、[涨跌停名单](https://tushare.pro/document/2?doc_id=298)。

## 采集与存储

沿用既有工作日20:00 `post`，复用已请求的涨停名单和全市场日线，不新增请求、定时任务或推送出口。`raw_data.consecutive_pool` 随现有 `post-market.yaml` 与 `daily_market` 信封双写。执行入口和 `--input-by` 要求不变。

目标日必须在SSE日历中为开放日；当日上海16:00前及未来日跳过。保存名单、对应原始日线及来源，以供报告重新计算。数量和金额分别核验；名单有效且没有连板股才允许0只/0亿元。金额缺任一成员时保留数量，合计金额为空，不用部分和冒充总额。名单重复、行日期错位、来源失败显式降级。

## 复盘展示

正式HTML组装器在③情绪区自动注入 `data-consecutive-pool-trend`。最近20个严格开放日，休市报告回溯至日历证明的最近开放日；自然日日历缺口拒算。

正文展示最新数量/成交额及两幅共用日期的趋势，数量单位为只，成交额单位为亿元。两种指标各自保留断点；逐日股票名称、代码、连板高度、成交额与覆盖状态放入折叠证据，缺口进入ops。旧归档只读重算，不修改历史正式报告或源文件；已有`consecutive_pool`块损坏/失败时不跨源掩盖。

旧归档的日线可从同日 `zhong_prefix_effect.evidence` 中读取，必须核验来源、日期与股票身份。没有可靠日线或连板身份的历史日保留待核，不联网补齐。

不改关注池、趋势池、最票、交易计划或评分规则。该趋势是事实指标，不自动作情绪强弱判断。

## 历史补采

用户2026-11-10追加授权：开发完成后补采过去一个自然月（2026-10-11至2026-11-10）。标准入口：

```bash
python3 scripts/tools/consecutive_pool_backfill.py --start-date 2026-10-11 --end-date 2026-11-10 --input-by USER
```

只按完整SSE自然日历选开放日；已有完整来源只读重算或幂等保留，否则仅请求对应日期的涨停名单与日线两个接口。仅补既有盘后信封的`raw_data.consecutive_pool`，原文件完整备份、SHA256及逐日来源/请求者回执保存到`data/reports/consecutive-pool/runs/`，并复用`sync_daily_market_to_db`双写。失败不覆盖旧档，覆盖降级保留旧结果；双写失败必须记录并可幂等重试。缺少整个盘后信封时拒绝凭空构造。不会运行完整post任务、发送推送或修改其他事实块。

默认复盘仍展示20个开放日；单独的月度预览可按补采窗口展示全部交易日。
