本文记录用户于 2026-11-17 确认的执行规则，以及 2026-11-16 事实日数据的修复口径。日常执行复用已核验历史，只新增当天全量快照，在本地对全量品种重新计算持续性指标。

Codex 本机自动化负责 21:00 调度。仓库中的 `scripts/automations/kaipanla_*.py` 负责批次落盘、恢复、验收、报告生成和发送。克隆仓库后可使用这些脚本，定时任务由 Codex 自动化管理。报告、历史和凭据均存本地。

UI 操作仅用 Computer Use 的 `cua_repl`。先查询运行应用，遇到 `com.kaipanla.www` 对应多个安装路径时，选择当次发现的运行 `Wrapper/kpl.app` 路径，不能固定临时目录。每次切页、切品种或切日期后重新读取状态，确认标题、品种、日期、数值稳定且属于当前页。按工具当前说明提交完成摘要。

## 每日执行顺序

1. 检查现有逐日归档的日期、品种身份、口径、覆盖与哈希，明确当天事实日期和待补缺口。
2. 采集百日新高完整板块页，并读取严格上一开放日的完整同口径快照作比较。
3. 采集异动提醒三栏，核对已触发、次日测算和监管日期。
4. 采集 ETF 涨跌排行、方向汇总、申购赎回和动向，核对行情日、申赎数据日和各榜的筛选范围。
5. 动态发现商品全部分类，逐类采集当天完整分页，以精选汇总交叉核对遗漏品种。
6. 对 `--`、冲突或异常缺失分批复核。重叠翻页、核对尾页，按小批次保存检查点。
7. 当天快照与已核验历史按品种身份、事实日期拼接，对全部品种重算连续上涨和 5/10/20 日窗口。
8. 保存明细、覆盖回执和报告版本，读回核验行数、日期、数值与计算结果。
9. 四个模块均通过核验后先归档再推送，保存发送回执和内容哈希。

首次建基线、缺失日期、新出现品种或已确认来源修订，才定向补采必要历史。已有完整的 20 日历史直接复用，不能每天重新翻查。失败刷新不得覆盖完整旧档，历史修正须先保存备份和修复回执。

休市或来源未更新时记录检查结果，同事实日同内容不重复推送。各模块独立保存进度。已核实的来源缺值留空并注明覆盖，有待核、漏采或关键来源失败时保存断点并暂停整份日报推送。锁屏、登录失败、加载失败应记录真实原因。

### 固定入口与断点恢复

在 `/Users/alyx/tradeSystem` 执行。以事实日 `YYYY-MM-DD` 替换以下命令中的日期。

```bash
date_to_check=YYYY-MM-DD
stage="data/reports/kaipanla-daily/.staging/$date_to_check"
python3 scripts/automations/kaipanla_daily.py calendar --date "$date_to_check"
python3 scripts/automations/kaipanla_checkpoint.py status --date "$date_to_check" --day-dir "$stage"
```

按 `remaining_slots` 续采，复用 `completed_slots`。商品单入口空值只对 `pending_commodity` 剩余项批量复核。每批用 `record` 保存，包含独立批次编号、明确的事实日、读取时间和证据。数据保存在临时日期目录，批次日志以哈希核验，原始 CSV 可在中断后重建。

```bash
python3 scripts/automations/kaipanla_checkpoint.py record --date "$date_to_check" --day-dir "$stage" \
  --input-by codex_automation --batch-id "商品-化工-01" --input "batch.json"
python3 scripts/automations/kaipanla_checkpoint.py materialize --date "$date_to_check" --day-dir "$stage" \
  --input-by codex_automation
```

可启动 `kaipanla_capture_bridge.py --date "$date_to_check" --day-dir "$stage" --input-by codex_automation`。Computer Use 在本机临时表单提交管道分隔文本，每行首列为证据类型，后续列按 `kaipanla_checkpoint.py` 的 `FIELDS` 顺序，事实日由批次写入。JSON 模式接受文件基本名到原始行数组的映射。单批重试用原编号和原证据，后续复核用新编号。明确更正时通过 `record --supersedes OLD_ID --reason "同日原页复核依据"` 追加完整替代批次，保留旧批次证据和哈希。采完关闭表单与进程。

ETF 涨幅榜及当天申赎列的验收凭证保存实际范围和表头日期。短榜在元数据边界写 `分页条数:高/低` 或 `分页条数:方向净申购/方向净赎回/个基净申购/个基净赎回` 的数字实值，说明核对到尾页、空榜或来源未披露的依据。同日已核实未显示的单个字段在相应边界备注 `源缺字段 证券代码或方向名称/字段名` 及证据。动向保存更新时间、两个榜单的源公布条数及页尾证据。商品分类及精选也保留各自尾页和独立计数。

```bash
python3 scripts/automations/kaipanla_daily.py finalize --date "$date_to_check" --input-by codex_automation
python3 scripts/automations/kaipanla_daily.py publish --date "$date_to_check" --input-by codex_automation
```

`finalize` 从批次日志重建原值并验收四个模块，再生成正式归档。已存前日快照先核验后比较，缺前日快照时标不可比，异动历史以可核实的本月边界验收。缺少的商品历史日期在计算中保留空位。`publish` 只接受 21:00 后的当日正式归档，重复成功回执直接跳过。尝试与成功回执独立于归档哈希保存，发送结果不明时先核对钉钉。回放采用 `replay --date YYYY-MM-DD --input-by USER --output <新目录>`，新版预览保留在指定目录，回执标记无发布资格。

## 百日新高口径

- 使用“按板块”视图，完整滚动加载。保存全部板块及各自新高股数、全页新高总数、今日新增数、个股名称代码与可见行情。
- 与严格上一开放日完整同口径快照比较板块新增、退出及数量增减。首次尽量建立最近 3～5 个交易日基线，缺少可比基线时明确缺口，未读到不能判退出。
- “持续增加”要求至少连续 3 个交易日的新高股数量严格递增，另列连续在榜天数。股票 `NEW` 标记不能当成新增板块，重叠板块数量不能相加冒充独立股票总数。
- 板块新增、退出描述的是页面独立分组变化。分组可能归入“其他”，不能据此推断原板块全部个股退出新高。
- 精选 3～5 只观察个股，从扩散或持续走强板块结合新增新高、持续在榜、成交额和当日表现筛选。列名称代码、板块、事实数据及简短 `[判断]` 理由，不给买卖指令或价格目标。

2026-11-26 起纳入同一份 21:00 日报。从开盘啦首页进入“ETF基金”，读取“行情”和“动向”。操作后确认已选标签、日期、筛选范围、排序列与方向。实测“行情”榜单的无障碍树可能显示空列表，画面仍有数据。此时截图核读名称、证券代码和同行数值，对照表头、排序箭头和页面首行，保留原始证据或摘录。截图与无障碍树均无法核实则记录采集缺口。

排行采用开盘啦当前可核实的榜单范围，实测个基默认覆盖宽基、行业、跨境、商品。记录当次实际筛选，明确是榜单两端的截取范围。方向汇总也记录自身分类范围。少于 5 条时保存实际行数和可核实的页尾或空榜提示。同值沿用来源顺序，跨日比较先核对筛选、排序和数据口径。

行情日期、申赎列日期、动向更新时间和读取时刻独立保存。页面提示境内披露一般在 T+1 早 8～9 点更新完毕，境外为 T+2。21:00 报告优先使用已到披露窗口且已在页面核实的最近数据，跨境与境内按实际数据日注明，来源尚未完整披露时标注已披露范围或留空。窗口到达本身不证明发布完成。盘后可保留当日已显示的申赎原值，下次仅补查尚待披露的日期或字段，历史快照按事实日期及读取版本保存。申赎金额、申赎份额、成交额和二级市场资金净额分别记录。保留金额及份额原单位，`--` 留空。

仅在已核实属于披露时差或来源不提供时，将该字段留空并注明覆盖，完整日报可发送。页面未加载、日期不明、漏采及数值冲突保留待核，暂停整份推送。每天按榜单或翻页批次落盘，记录排序范围、行数、时间和哈希，续跑复用已核验批次。

钉钉正文保留“ETF趋势〔判断〕”短段，交代行情日、申赎数据日和动向更新时间。用已核验的完整动向榜对照新进、退榜和延长，同名方向基金只数变化时注明样本变化。明确的反向申赎数值才支持“由申购转赎回”等结论。区间终点以页面为准。复用已有开放日历窗口内已核验的历史归档，按实际披露日期向前去重，取最近至多三期金额，仅比较同方向、同范围且基金只数一致的记录。相邻动向榜更新时间、范围及只数均可比时，摘要列出天数、累计申赎金额、区间涨跌幅的前值和现值；缺少可比证据时标示本期值。完整比较、榜单及覆盖放本地 HTML。

## 商品现货全量筛选

### 样本与历史

以动态发现的全部分类和各类完整分页建立样本，按名称、分类、报价标识核对身份并去重，与精选汇总交叉核验。分类数和品种数随来源变化，不能固定为 15 类、17 类或 381 项。同名异规格不能直接合并，指数与现货报价分别标识，单位必须一致。

当天小涨、持平、下跌和缺报价者全部进入历史覆盖核验，不能以当天涨幅达到 3%、涨幅排名或精选前 N 项作为持续性筛选前置条件。近 20 个有效报价日以来源可核验的日期序列为准，应有日期缺失不能跳过并伪装成连续。新出现品种没有可核验历史时保留缺口，不能用当前身份或成员关系虚构历史。

### 阈值与计算

| 类别 | 条件 | 展示要求 |
| --- | --- | --- |
| 单日明显上涨 | 当日涨幅 ≥3% | 独立提示，不替代持续性筛选 |
| 严格连续上涨 | 当前尾部连续 ≥3 个有效报价日均上涨，且该段累计 ≥5% | 标连续日数和该段累计涨幅 |
| 缓慢累涨 | 任一完整 5/10/20 日窗口累计 ≥5%，上涨日数达到窗口的 60% | 标窗口和上涨日数，不称为连续上涨 |

以上为工程观察参数，可按用户要求调整。上涨日要求涨幅严格大于 0，持平不计上涨日。缓慢累涨可包含持平或回落，严格连续上涨遇非正涨幅即终止。遇缺失中断核验，不补零、不跳缺口拼接连续段。连续段触及已核验窗口边界时写“至少 N 日”。

累计涨幅优先用同源、同单位、同规格的窗口起始前报价与期末报价核算。若只有完整同口径逐日涨幅 `r_i`（百分数），采用 `100 × (∏(1 + r_i/100) − 1)`，标明页面涨幅四舍五入带来的近似。N 日涨幅须对应 N 次变化，端点法需要相应起始前报价，不能把 N 个价格点误算成 N 日涨幅。

每个品种均保留 5/10/20 日累计涨幅、上涨日数、当前连续上涨日数及该段累计涨幅。完整性按品种和窗口分别记录，某一窗口不足不应抹掉其他完整窗口的结果。

### `--` 复核顺序

1. 重读稳定页面，核对日期、品种和加载状态，排除旧页缓存。切换品种后即使日期标签未变，也要重新选择目标日期并等待数值稳定。
2. 检查同品种分类页。存在明确数值时使用分类页数值并保存来源，精选汇总的 `--` 不得直接记为缺报价。
3. 分类页仍缺失时，查看详情的当日价、前一报价日价格、日期、单位和报价依据。依据完整一致时可补算涨幅，并保存原始价格与计算依据。
4. 仅有 `--` 不能填零，变动额显示 `0.00` 也可能经过舍入。字段不一致保留待核，核验后确认来源确无报价才标缺失。

分别记录价格是否存在、涨幅是否显示、来源是否加载完成、是否已经复核。缺失突然增加时优先排查漏页、漏分类和加载问题，逐项补核后再下结论。每次报告给出样本总数、实际核验数、有效日涨幅数、各窗口完整数及未核验名单，并与前日比较。
