# 重点涨停股票的买一盘口

已有盘中异动任务在每个 SSE 开放日的 09:32–11:22 和 13:02–14:52 每十分钟采样。保留当批冻结且有前一开放日出处的核心、手写锚点，以及本日原始最高成交价已触及官方涨停价的股票。后一组从首次观测到触价的批次起跟踪。股票范围沿用原非 ST 行情样本；没有价格限制的证券单列，北交所一档可用性单独按实际回包计算。不同分组按代码去重。

复用已有的同一次新浪行情和同一日 Tushare 涨跌停价响应。早期本地限价缓存只保留下限时，回放从带来源回执与哈希的本日完整限价原件提取上限。该时点尚无官方参考时，先保留已知核心的实收盘口与报价，限价取得时刻可另行核对。对日内新触价样本，需要有当时取得的行情、真实最高成交价及参考限价才能核实其来源。原始盘口按选定证券逐股绑定到原批次、原文件 SHA-256、证券、成交价和源报价时刻。

| 字段 | 使用方式 |
|---|---|
| `first_observed_high_at_limit` | 第一次观察到累计日高已触价的报价时刻，真实首次触价可能更早。 |
| `batches[].rows` | 含股票、源报价时间、最新/最高成交价、实际涨停价、一档买卖价及股数；`fixed_reasons` 标记前一日核心、手写锚点口径。 |
| `buy_queue_amount_yuan` | 最新价与买一价都等于涨停、买一有效正股数、卖一明确零价零量、股数单位可核验时，以买一价乘股数，金额保留到分。其余留空。 |
| `queue_changes` | 两端均有确认挂单金额时，列同股相邻两次观察的起止时刻、金额及差值（元）。要求同半场、同源、同一冻结样本、同一上限；批次和个股各自相隔 7–13 分钟。缺档、缺股、重复槽和跨午休均中断。 |
| `coverage` | 区分有效价格条数、带有效买一条数、双边可核验条数及确认存在涨停买单队列的条数。整日没有任何双边可核验记录时，最后一项留空。 |

相邻队列净变化可能来自新委托、成交或撤单，成交价在两个观察点都为涨停时，中间也可能发生开板或回封。逐笔委托来源和成交所需的时间精度另行核验。盘后涨停名单的首次封板、末次封板和封单金额分别留在原盘后归档。

每日结果保存于 `data/reports/limit-up-orderbook/YYYY-MM-DD.json`，限价证据保存于同目录的 `references/YYYY-MM-DD.json`，小样本实收盘口另存于原行情批次的 `limit-up-book-source.json`。实际采集沿用原有十分钟任务，无新增请求或通知。可从项目根目录只用原始批次回放：

```bash
/usr/bin/python3 scripts/tools/limit_up_orderbook.py --date 2026-11-27 --input-by USER
```
