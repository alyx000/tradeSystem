# 逐股炸板池

工作日 20:00 盘后采集将东方财富炸板股池保存到 `raw_data.broken_board_pool`。与原有炸板总数使用同一接口和参数，每次只请求一页，超时单独降级。归档保留原响应、SHA-256、来源日期和取得时刻。逐股记录证券代码、名称、首次封板时间、炸板次数、最新成交价、涨停价和成交额。盘后价格单位为元，时间为上海时间，金额为元。

只有来源日期与事实日相符、接口状态成功、已返回全部宣称的行且证券身份可核对时才发布数量。明确返回同日零行且总数为零才认定空池。空响应、日期无法核验、缺页或连接失败时，数量和涉及它的比率留空。已核验成员缺少部分明细字段时，保留成员和数量，在逐股缺口中写明字段。当天重跑遇到外部故障会优先取同日有完整来源证据的旧归档。

`raw_data.limit_up` 中原有 `broken_count`、`broken_rate_pct` 和 `seal_rate_pct` 名称保留；剔 ST 的比率使用同一套名称规则同时过滤收盘封板股和炸板股。Tushare 收盘涨停源排除 ST，若东财当日炸板池含 ST，仅发布双方剔 ST 后的可比比率。两个来源出现重叠证券，或收盘涨停名单自身未核齐时，比率留空。统计范围限于对应来源榜单。首次封板时间和炸板次数只能说明首封和累计次数，中间每次开板、回封时刻不在这个日榜中。

手工验证使用如下命令。它只刷新独立日档，不修改既有盘后信封，也不推送。

```sh
python3 scripts/tools/broken_board_pool.py --date 2026-11-27 --input-by USER --save
```

`data/reports/broken-board-pool/YYYY-MM-DD.json` 同时保留三种证据：

- `broken_board_pool` 保存东财源原始名单。若历史查询的源日期不等于请求日期，保留原因。
- `prior_post_summary` 保存原盘后已报告的正数总量。旧版可能把源失败记作 0，独立出现的历史 0 保留待核。
- `daily_touch_only` 独立复算“当日日线最高成交价等于涨停价、收盘回落”。使用同日归档的日线、限价和 ST 名单，逐个校验记录日期、唯一性和取数回执及哈希。在已有归档覆盖范围内给出代码、价位与 ST 身份。日线无法核验是否形成封单、首次封板时间与炸板次数，不能用该样本增加或替换东财名单。

收益反馈可以用同日证券代码再接下一开放日日线。以上采集不改变交易计划或观察池。
