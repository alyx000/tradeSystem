# 通达信平均股价和微盘股的盘中5分钟K线

在既有180秒盘中任务完成原市场扫描、四宽基成交额和价格提醒后，按同一5分钟闭合槽归档通达信平均股价（880003.TDX）和通达信微盘股（880823.TDX）。本项结果保存在CLI JSON的 `tdx_index_5m_archive`，不会产生消息，也不会改变原有提醒及其状态。

## 来源及覆盖

逐代码请求 pytdx `get_index_bars(0, 1, code, 0, 800)`。0表示原生5分钟、1为沪市行情站，800是近端最大取数根数。pytdx按本次请求的证券代码解码源时间和OHLC；通常协议不回显证券身份，有回显时必须与请求一致。每根保留源时间、源节点、请求代码/市场/周期、采集时间和请求者；价格沿用已解码的数值，不再缩放。日期取源K线的上海交易日。这里归档价格，四个东方财富宽基的成交量额仍按其自己的来源与日档定义。

每天上午09:35—11:30、下午13:05—15:00，各指数48个5分钟闭合点，两指数共96个。实时只接纳截止已完成槽；日历必须能证明当天和严格上一开放日。单代码每次优先使用返回完整目标时间窗的节点，均不完整时优先目标日覆盖较全、包含最新应到槽的节点，再比较历史可补根数，仅取单节点有效回包，缺根留空。原生行重复、倒序、非法时点、身份冲突或价格范围错误则淘汰该节点响应。可用严格上一开放日的同源返回行补缺；每半场连续6根且无冲突才形成一根30分钟OHLC。单点报价和日线不能恢复时段内高低。

写入共享数据目录 `data/reports/tdx-index-5m/YYYY-MM-DD.json`，保留有效数、应有数、已到期的缺失槽与原值冲突。相同数值不覆盖首次采集时间；与已存闭合值有出入时保留两份证据并停用对应30分钟聚合。日档哈希校验、跨进程锁与同目录原子替换沿用指数归档逻辑。取数回执在 `attempts/YYYY-MM-DD/` 分列本次各日期应到与实得根数、目标日和上一日覆盖、按日累计档案覆盖，并标记当次来源失败；同一槽已经完整就不会重复请求。来源失败时保留已有原值，周末和盘外的常规定时入口不模拟盘中数据。

## 指定日期核验

在实际运行工作树执行 `python3 scripts/tools/tdx_index_archive.py --date YYYY-MM-DD --input-by USER`，只采指定的已收盘开放日。小时、分钟必须有证券源时间，近期800根以外可能无法恢复。每次取数在两个证券之间并发，每股按已配置的来源节点依次尝试，套接字超时与总预算沿用通达信盘中监控。

2026-11-28的实际核验中，11-27的两指数5分钟请求均未能连接已配置通达信节点。日档记录有效0/96，每票48个缺口；当日既有日线、单点价格和高周期结构不能用来补齐。待下一交易日可用的分时源或同口径历史文件出现后方能确认真实连续采集。
