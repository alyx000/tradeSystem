# 前夜核心与同题材昨日涨停股的开盘集合竞价

按观察日保存 09:25 最终撮合的成交价（元）、成交量（股）、成交额（元）、当日除权参考昨收和竞价涨幅。09:15 前是选样截止，09:25 是竞价阶段的结束，供应商通常在 09:26～09:29 发布，归档再单独记录请求、返回及实际取得时间。09:25 记录为市场竞价阶段结束时间，专用源只返回交易日期，逐笔撮合秒数未披露。历史回收记实际取得时间。证据支持盘后复核。

## 事实来源

使用项目现有 Tushare 传输和账户权限，按目标日查询专用 `stk_auction`。接口的 `price` 为成交均价，开盘集合竞价以单一价格成交。量、额及均价交叉核对，允许单股半分或总金额一元中的较大舍入误差。保留原字段、证券代码、交易日期和来源。 [Tushare 当日集合竞价](https://tushare.pro/document/2?doc_id=369) · [上交所交易规则 3.5.2](https://www.sse.com.cn/lawandrules/sselawsrules2025/stocks/exchange/c/c_20260424_10816482.shtml)

日线开盘与当日参考昨收取同日盘后归档，作为独立对照，成交三项均须来自竞价专用源。专用源缺昨收时可用已核验的当日日线参考昨收补足。两处昨收或开盘价冲突时保留缺口。09:30 统计、09:31 首根分钟、盘前虚拟撮合价格、未成交封单各自有不同时间口径，此模块只处理开盘集合竞价最终成交。 [Tushare 的 09:30 统计及样例](https://tushare.pro/document/2?doc_id=353)

## 样本

- 核心取严格前一 SSE 开放日手写确认和正式复盘人工最票，仅使用今日 09:15 之前已登记且可核验证券身份的版本。
- 同题材涨停股取严格前一开放日归档收盘涨停名单，核对同日身份。候选须属于含前夜核心的已核验题材，或属于事前选中、并有该事实日完整成员的细题材。此前日涨停证据来自该日完整名单；各核心的明确同看对象、手写分组仅按有据可查的同题材关系纳入。
- 行业与题材名称不互换。结构化题材成员沿用项目现有的 ≤300 只范围，避免将热门大集合自动扩成对照。手写同组只代表该稿点名的成员。收据列出来源覆盖、被排除的泛概念数量、观察范围内的组名和核心代码。
- 前夜核心、同题材昨日涨停及两组交集分别计数。按完整代码去重；旧日样本首次保存后固定，重跑使用原样本。源发布时间晚于截止、资料缺失、当日题材掉榜都不能用今日成员补以前。

## 入口、重试和证据

```bash
/usr/bin/python3 scripts/tools/course_opening_auction.py --date YYYY-MM-DD --input-by USER --json
/usr/bin/python3 scripts/tools/course_opening_auction.py --date YYYY-MM-DD --input-by USER --dry-run --json
```

既有 09:32 盘中事件槽在上海当日 09:32～09:34 独立请求专用竞价接口；即使该子任务失败，原采样仍照常返回。20:00 同一入口补缺，并用盘后正式日线核对早盘的取得记录。历史重试记录真实请求时点。

日档为 `data/reports/course-opening-auction/YYYY-MM-DD.json`，按日加锁、校验摘要并原子替换。试运行仅在内存计算。休市、未来及上海当日 09:29 前跳过。重跑只补缺行和缺少的昨收依据；补昨收时逐股核对原成交状态、价格、股数、金额四项；保留首次成交原始响应和采集时间，新增昨收来源、核验时间及派生涨幅。冲突保持原值并记录原因。无外部推送，无业务表写入。

只有供应商明确给出零股、零元，且成交价为零或空值才计入“无撮合成交”，价格留空。连接失败时返回行数为未知，成功空回复记录 0 行；两者都不将缺少的标的判成零成交。价格、量额、日期、唯一代码失败逐项保留原因；整日响应已返回样本但仍缺代码，或撞上 8000 行上限时，保留已到数据，再按同日和完整代码定向补缺。全源连接失败、空回复、错日均仅请求一次。逐次参数、返回行数和独立失败均列在 `latest_attempt.requests`。每次替换先按原摘要保留上一版回执在 `revisions/YYYY-MM-DD/`。结果同时列 `matched`、`explicit_no_match`、`observed` 和两个样本分别的覆盖。成功/跳过退出 0，部分完成/来源失败退出 2。
