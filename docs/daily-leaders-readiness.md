# 每日最票：当日数据就绪与延迟重试

工作日 21:00 仍由原 `com.alyx.tradesystem.daily-leaders` 触发，沿用精简确认稿。
生产入口：`python3 scripts/main.py daily-leaders propose --push --wait-ready --input-by launchd`。

## 发布前检查

任何 `propose --push` 都必须通过检查；不带 `--push` 的本地诊断仍可生成降级稿。

- 当日 SSE 日历必须存在；明确休市直接静默跳过，未知日历视为未就绪。
- `daily_market` 必须有目标日盘后信封，外层/内层事实日一致，生成时间为该日上海时间16:00之后。不得用前一日数据替代。
- 复盘预填实际消费的连板梯队、最强题材、同花顺/东方财富行业与概念资金流、行业/概念排名必须存在且来源成功。六项带交易日期的块逐行核对目标日；梯队代码/板数、题材涨幅/涨停数及资金流关键数值有效，行业/概念排名必须有板块名称和有效涨跌幅。快照读取期间发生变化则重新读取。
- 连板梯队、最强题材允许真正空榜，但必须有相同目标日的明确 `empty` 来源回执；缺失、失败不能当成零。
- 复用本轮原有的日线、股票名称与申万分类请求，不增加行情接口。日线至少4000条，代码唯一，全部日期为目标日且量价有效；覆盖上市A股至少98%，每条行情身份/名称有匹配。沪深申万行业覆盖至少98%；成交额≥20亿元的股票须有行业分类。
- 成功检查随候选 JSON 保存 `readiness`（事实日、盘后生成时间、日线及股票宇宙数量）；失败在评选与报告写入之前停止，保留已有报告。

这里没有新增断板报告、趋势池或择时报告输入，也不改变选股与人工确认规则。附加报告尚未接入，不作为等待条件。

## 重试与停止

- `--wait-ready` 仅与 `--push` 同用，固定上海工作日当日21:00（含）至23:00（不含）。
- 数据未就绪每300秒重新检查，每次重新打开数据库、重建预填及 provider，读到晚到的数据。
- 截止时仍未就绪以退出码75停止，不推送候选稿；日志保留执行日期、请求者与缺口。不会跨日补发或新增独立调度。
- 生成耗时跨过23:00也不发送；生成后的本地报告可保留查看。
- 只有数据未就绪会自动重试；其他程序错误直接退出。钉钉失败返回非零但不自动重发，避免把不确定送达变成重复消息。
- 不带 `--wait-ready` 的人工 `--push` 也执行检查，失败立即退出75。
- launchd 继续每日单次启动同一任务，不加 `KeepAlive`，重试由这次进程内处理。重载配置不立即执行，也不发送验证消息。
