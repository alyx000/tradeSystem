# 复盘 Sites 按需发布（默认发布已取消）

2026-11-03 用户随后明确取消：“以后复盘默认发布到同一个私有 Site 这个取消吧”。此更正取代此前默认Sites交付偏好。以后生成或修订复盘默认交付本地HTML，不自动上传、发布或重试此前失败的发布。仅当用户明确要求发布到Sites时，才参考下方流程；现有站点及本地文件保留。

## 既有站点（非自动发布目标）

- 仅在用户明确要求发布或更新时，从其指定的本地项目读取 `.openai/hosting.json`，核对并复用既有站点；不能因存在配置就自动发布。
- 实际站点ID、访问范围和URL按本机配置及原生服务回执核验，不保存到此通用规范。URL存在本身不证明发布成功。
- 保留用户已确认的访问范围，只有明确要求才更改。

## 仅在用户明确要求Sites发布时执行

1. 先按多Agent流程完成日期/来源、计算、图形及浏览器验收，保留正式报告和验收附件；Sites不替代这些要求。
2. 使用当前安装的Sites技能，先get_site核对站点访问范围，获取临时源码凭据，以官方source helper打开已有源码，使用返回的checkout_path继续。凭据只在内存中经隐藏stdin传入，不写文件或输出。
3. 将合格报告加入`dist/YYYY-MM-DD.html`，更新`dist/index.html`为最新复盘，更新`dist/archive.html`的日期入口；保留已经发布的历史日期页。旧报告发生明确授权的修订时更新其日期页；首页只指向最新报告日。
4. 同步报告实际链接的交付附件，维护来源跳转。只打包HTML和必要的已交付附件，不复制数据库、YAML、原始来源包、环境配置或整个tradeSystem仓库。未发布的前一日链接改为复盘目录，不保留失效本地地址。
5. 保留已有图表、股票名称代码、搜索、证据展开、手机布局、事实日期及缺口；核对关键数值和站内链接。完整本地验证与部署后网址验证分别记录。
6. 官方source helper完成源码commit/push与静态归档打包；使用返回的同一project_id、commit_sha、archive调用原生Sites发布。已知owner-private使用private发布，其他访问范围按Sites技能处理。失败复用同一Site和已有版本，不重复创建。
7. 等到部署返回succeeded及URL才报发布完成；失败则交付本地报告并说明发布缺口，保留待发布源码继续恢复。正常交付优先给Site网页链接，并可在Codex侧栏打开。

此偏好不新增定时任务、站点云端采集、市场推送或业务写入。普通复盘请求不触发上述发布步骤；只有明确要求Sites发布才执行，也不自动创建每日发布调度。
