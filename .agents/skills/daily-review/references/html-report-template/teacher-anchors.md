# 每日老师核心锚点与指数关键点位

用户要求两项内容每天固定进入复盘 HTML。第9路每天重新阅读老师原始记录，主会话整理为 `teacher_anchors_<REPORT_DATE>.html` 放在本次 scratchpad。正式组装器只读所选 `--trade-db` 的 `teacher_notes` / `teachers` 核对记录、归档日和引文，再生成老师章节中的两张默认展开、可手动收起的表和原文依据；不新增定时任务、不写老师观点或计划。

## 每日必做

1. 覆盖本次老师观点窗口：每位老师的核心观察对象、确认/失效条件、个股或板块锚点。没有明确锚点须写明，不能用行情事实自行代拟老师观点。旧观点可作对照，但标历史归档日；原文发言日期不清或与归档日不同必须披露。
2. 提取老师明确提到的指数名称、点位/区域、周期和性质（前低、争夺位、支撑、压力或条件情景）。同指数的不同老师观点分别保留，不合成所谓共识价位；不把动态均线旧值当今日新值。未给具体数字或没有可核实归属时，写“未提供”或“待核”，不猜代码或纠正转写。
3. 每行必须带真实 note ID、归档日、逐字引文和保留条件的简要归纳。引文可仅忽略空白差异，不能改数字或标点。记录来自哪个老师由数据库确定；代转来源（如财智归在鞠磊来源组）在观察对象或摘要中说明真实作者。
4. 本模块全属老师观点。`pending` 表示待盘面验证，`historical` 是历史观点，`uncertain` 是待核原文，`not-stated` 表示来源未给具体点位。缺材料不得填“没有观点”或“无关键位”。
5. 主会话对照原文复核归纳是否保留条件。程序只证明记录与引文匹配，不证明语义推导、价格预测或观点正确。次日重新核验，禁止复制旧文件仅改复核日期。

## 输入示例

输入文件仅允许八项属性的纯文本 `p`，用 HTML 转义保存引文及正文，不嵌表格、链接、脚本。下面的 note ID、日期、引文仅说明结构，使用时须换成本次真实记录。

```html
<p data-kind="anchor" data-report-date="2026-11-01" data-note-id="1093" data-source-date="2026-11-01" data-subject="情绪修复" data-level="" data-status="pending" data-quote="跌停票少于3家就是超预期强修复。">跌停收敛是老师的观察条件，需与量能及进攻方向共同验证。</p>
<p data-kind="level" data-report-date="2026-11-01" data-note-id="1093" data-source-date="2026-11-01" data-subject="上证指数" data-level="3574" data-status="pending" data-quote="跌后上证指数顺势击破3574点位置也可以满足等比跌幅条件">来源前低观察位；须保留其下探后的修复条件，不当作保证有效的支撑。</p>
```

`data-kind` 固定为 `anchor` 或 `level`；`level` 行的 `data-level` 不得为空，可填写“未提供”“归属待核”。同一 note ID 与同类观察对象不能重复。指数点位的数字或区域由作者从原文整理；有转写疑点必须用 `uncertain`。

## 固定展示与校验

- 保持原15个章节和16类行情图；两项内容唯一归属“老师观点”，标题及两张完整表默认可见、可手动收起，原文引文默认折叠，支持搜索、展开全部、来源跳转和手机局部横向滚动。
- 缺输入自动显示 `missing-data`；数据库读取失败、记录不存在、日期或引文错配显示 `source_failed` 并进入数据缺口。只整理了一类时，另一类明确缺失，不静默删除。
- chunk 不手写这两个自动模块。Python 调用可先用 `review_teacher_anchors.load(path, report_date, db_path)` 获取核验结果，再将同一 `teacher_anchors` 传给 `render_report/validate_report/write_report`；正式 CLI 自动完成。
- 对生成块与核验结果逐字对账，不能移动至其他章节或重复注入。经对账的本模块折叠证据单独计量，上限8000字/40行；原正文预算不变。超过时精简重复描述，不能删掉条件和出处或擅自截断老师名单。
- 验收：当前实际报告两张表、数字与归属、来源跳转、搜索、三种宽度；另测缺文件、坏来源、历史日期、未来日期、引文不符和篡改输出。
