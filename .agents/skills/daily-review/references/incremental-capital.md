# 当下增量资金推断

每日复盘 HTML ①大势必答：**当前可观察的增量更可能来自什么渠道，具体依据是什么？** 主会话在第1路两融/成交、第2路板块、第3路风格、第4路机构席位、第5路ETF素材到齐后综合填写。保留一条默认可见结论与3～8条折叠证据；不新增采集任务、业务写入或推送。

## 判断顺序

1. 先核对最近已收盘开放日T、上一开放日及最近5个开放日；报告日与事实日分开。检查总成交额变化、板块增额与份额变化，判断是否仅是换手放大/存量轮动。成交额是交易活跃度，不能当新增资金金额。
2. 分别检查下表渠道，正向、负向和无法核验的证据都保留。比较T与上一开放日，同时列最近5日累计与正负天数；历史窗不完整就标未计算，不以稀疏窗口冒充连续5日。不同口径不求和、不算“资金来源占比”。
3. 给出最有依据的候选和至少一个替代解释，说明为什么其余候选不成立或尚不能识别。明确“有渠道增量迹象”与“全市场净增量已确认”的区别。两类同日完整支持（至少一类对应渠道的直接证据）才允许给具体候选；同一份额差与其金额估算只算一类，不同ETF也只算一类。中/低可信度为工程分级，不是统计概率。
4. 全是量价/风格代理、来源滞后、相互矛盾或证据不足时，结论写“无法识别”，仍解释已观察到的事实和最值得继续验证的假设。滞后两融/ETF数据保留其来源日，只作历史背景；周末只描述最近开放日历史线索，当前增量无法识别，不能将周五数据改标周日。
5. 给出下一开放日的确认/证伪条件，例如对应渠道继续净申购/转净赎回、融资净增加/回落、板块放量但市场总额下降；不输出买卖指令或价格目标。

## 证据与可推断范围

| 渠道/代理 | 必须展示的具体依据 | 能支持什么及反证边界 |
|---|---|---|
| ETF申赎渠道 | `fund_share` 两日份额差、日期、样本数/覆盖；当日收盘价换算的净申赎估算额；宽基互斥归属、拆分处理；近5日若完整则列累计与方向天数 | 申赎渠道扩张迹象；不等于二级市场净流入，实物申赎/套利亦可改变份额，不能识别国家队、公募、保险或散户身份 |
| 融资渠道 | 融资余额两日差，或融资买入减偿还，来源日、单位、沪深北覆盖；近5日同口径累计 | 杠杆渠道增减；融资余额与含融券的“两融总余额”必须区分，不能拿后者直接认定融资净买入；T-1数据不能证明T入场 |
| 机构席位局部买盘 | 全部机构席位净买/净卖、样本、单日/多日段、上榜原因和集中方向 | 仅龙虎榜样本的机构交易线索；存在榜单选择偏差，不能代表全市场机构增量，更不能据“机构专用”识别公募或保险 |
| 公募募集背景 | 募集/成立事实日期、实际募集规模与状态、股票配置范围；只有实际披露才列金额 | 潜在资金供给，募集不等于已经建仓，募集目标不算实际募资；不能单独当入市直接证据 |
| 成交额与风格 | 市场总额及日变化、板块增额/份额变化；容量/小微盘/连板反馈的数值和完整窗口 | 验证渠道假设的方向一致性或提示存量轮动；放量不等于净流入，小盘活跃不等于散户入场，趋势上涨不等于机构入场 |

北向数据继续禁用。无法直接识别游资、散户、公募、保险、国家队时不得强行贴身份。信息流“大单/主力净流入”是交易分类代理，不作为投资者身份识别。ETF/融资/龙虎榜覆盖不同且可能重叠，绝不相加为全市场增量。

## HTML契约

摘要放在`s1`的默认可见区，用`p[data-incremental-capital="verdict"]`，标`data-as-of`及`data-reviewed-through`为报告日（逐条事实日期由证据行给出）、`data-source-status="complete|partial"`、`data-confidence="low|medium"`。`data-candidate`及必须可见的名称：

| 值 | 可见名称 |
|---|---|
| etf | ETF申赎渠道 |
| margin | 融资渠道 |
| institution | 机构席位局部买盘 |
| rotation | 存量轮动 |
| mixed | 多渠道迹象 |
| unknown | 无法识别 |

摘要必须包含`[判断]`、增量资金、候选、中/低可信度和一句确认/证伪条件。最多中可信度，不能表示已确认最终出资者；unknown固定低可信度。mixed须两种直接渠道支持；rotation须成交额证据，不把单日缩量直接定为没有场外流入。

详细依据放在同一节既有`details.evidence`，使用唯一`table[data-incremental-capital="evidence"][data-as-of="报告日"]`。表头固定“作用 / 来源 / 日期窗口 / 具体依据 / 推断与局限”。每行含：

- `data-role="support|counter|gap"`：可见“支持/反证/缺口”；反证可写有依据的替代解释，不能编造负面数值。
- `data-source="etf|margin|institution|turnover|style|fund-issuance"`：可见ETF/融资/机构席位/成交额/风格/公募募集及具体接口或归档路径、字段与样本覆盖。
- `data-window-start`、`data-as-of`：合法、不晚于报告日、起止都可见；单日同值。事实原值/对比值/差额/单位标`[事实]`，支持理由及解释边界标`[判断]`。
- `data-source-status="complete|partial|source_failed|missing-data"`：非完整状态必须可见；失败和缺源只作gap，不参与支持计数。具体候选必须有两类当日complete支持；滞后行可以展示，不计为当日支持。

支持、反证/替代解释、覆盖缺口三方面均检查；无具体来源缺失时gap也可用complete说明“覆盖局限：仅渠道数据、最终投资者身份不可识别”。出现任一不完整行，摘要标partial并在ops明确写“增量资金推断”及缺项。unknown可保留已知证据，不必满足两类支持。

尚未整理证据时使用唯一`p[data-incremental-capital="missing-data"]`，日期属性同上，状态`partial|source_failed|missing-data`，可见“[判断] 增量资金：无法识别”，并在ops解释原因。旧chunk未提供模块时组装器自动补这一缺口；**不会自动生成来源判断**。

## 验收与边界

生成器校验唯一性、章节/可见性、日期、数值证据、来源类别、最低支持条件、反证与缺口结构；**不自动核实Agent填入的数字真实性、方向推理或投资者身份**。主会话须逐条对照原始素材，确认原始来源/字段/计算和反证匹配，保留查询记录，不能把结构校验通过称为事实复算完成。

正文只加一句，不复制ETF/机构原始全表；详细证据引用既有来源，维持原正文与附录预算。测试：`python3 -m pytest scripts/tests/test_daily_review_incremental_capital.py scripts/tests/test_daily_review_html_report.py -q`及`make check-scripts`。新报告采用该流程；旧归档不改写，预览使用非canonical路径。
